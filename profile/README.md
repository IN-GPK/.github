## 📂 Como utilizar esta organização

Esta organização reúne múltiplos repositórios de projetos internos. De forma geral:

- Cada repositório representa um projeto, automação ou iniciativa específica
- Todo projeto deve possuir um README com instruções de uso e contexto
- Repositórios podem conter código, documentação, scripts ou modelos
- Padrões comuns são compartilhados entre os projetos da organização
  
---

## 📌 Observações

- Todos os projetos e soluções aqui desenvolvidos são voltados para **uso interno** da Gramado Parks.
- O acesso a este repositório e aos dados tratados seguem e devem seguir as **normas de governança de dados e confidencialidade da empresa**.
- Para solicitações de novos relatórios, dashboards ou automações, utilize o canal oficial interno de chamados.

---

## 🛡️ Governança de Código

- Todo projeto deve possuir documentação mínima (README)
- Commits devem ser claros, objetivos e rastreáveis
- Pull Requests devem conter descrição e passar por revisão
- Alterações em código legado devem incluir documentação
- Código compartilhado deve priorizar reutilização e padronização

---

## 📣 Comunicação e Solicitações

- Demandas de novos projetos, relatórios ou automações devem ser feitas via canal oficial interno
- Dúvidas técnicas podem ser direcionadas ao time de Desenvolvimento
- Demandas analíticas e dashboards devem ser alinhadas com o time de BI

---

## 🚀 Nossa missão

Desenvolver soluções robustas, escaláveis e bem documentadas que apoiem as operações e a tomada de decisão da Gramado Parks, integrando sistemas, automatizando processos e transformando necessidades de negócio em produtos digitais confiáveis.

---

## 🔭 Visão

Ser o núcleo técnico de desenvolvimento da Gramado Parks, promovendo padrões de engenharia, reutilização de código, automação inteligente e integração entre dados, sistemas, pessoas e processos!

## 💎 Nossos Valores

- 🧱 **Código sustentável**  
  Soluções pensadas para manutenção, escalabilidade e evolução contínua.

- 📦 **Padronização e organização**  
  Estruturas claras, versionamento adequado e boas práticas de desenvolvimento.

- 🐳 **Ambientes reproduzíveis**  
  Uso de containers, automação de setup e consistência entre ambientes.

- 🔄 **Integração acima de silos**  
  Sistemas, dados e equipes conectados de forma eficiente.

- 📚 **Documentação como parte do código**  
  Código sem documentação não é considerado completo.

- 🤝 **Colaboração e revisão**  
  Desenvolvimento orientado a compartilhamento, revisão e aprendizado contínuo.

- 🔐 **Responsabilidade e segurança**  
  Respeito às normas internas, governança de dados e segurança da informação.

## 🧰 Escopo Técnico

Esta organização[<sup>?</sup>](https://docs.github.com/en/organizations/collaborating-with-groups-in-organizations/about-organizations) centraliza projetos e iniciativas relacionadas a:

### 📦 Tipos de Projetos
- Desenvolvimento de aplicações internas, externas e APIs
- Automações, rotinas agendadas e pipelines de dados
- Projetos de BI, analytics e engenharia de dados
- Integrações entre sistemas internos e externos
- Scripts, serviços e ferramentas de apoio técnico
- Containerização e orquestração de serviços

### 🧱 Padrões Técnicos
- Versionamento com Git e GitHub
- Programação Procedural e também Orientado a Objetos. <sup>*a que mais se adequar</sup>
- Uso de containers para ambientes consistentes
- Integrações baseadas em APIs REST e também em RPCs <sup>*em casos específicos</sup>
- Bancos de dados relacionais e analíticos

Tecnologias mais utilizadas incluem (mas não se limitam a):

**Python • Node.js • Bun.js • PHP • Docker • K8s • SQL • Power BI • APIs REST**
